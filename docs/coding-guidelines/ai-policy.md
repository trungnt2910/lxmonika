# lxmonika AI Policy

This rule governs how tools based on Large Language Models or Generative AI (AI tools) can be used
for the development of `lxmonika`.

This is a non-exhaustive rule that is subject to change.

## General Rules

As a general rule:
- "AI slop" (low-quality AI content) is strictly prohibited.
- No AI output or content based on AI output in the `master` branch.

## Documentation

Due to the highly technical nature of `lxmonika`, a strict policy against AI-generated documentation
is enforced due to its unreliability.

### DO
- Write documentation only for areas you have a deep understanding about.
- Use proofreading tools that do not significantly alter your content.

### DON'T
- Use AI to generate documentation on areas you are not familiar with.
- Use AI to paraphrase your own work, or paraphrase AI-generated content.
- Use AI to research on an area before writing documentation.

## Code

AI-assisted coding is allowed as long as there is a **human in the loop**.

Code generated by AI must undergo manual human review and refactoring before being committed.
Direct AI output is strictly prohibited.

You, the contributor, are ultimately responsible for all code you contribute and must understand
every line of code under your name.

### DO
- Use AI tools to research techniques and brainstorm solutions.
- Use AI tools to try out prototypes on a separate branch or separate repository.
  + [`BootstrapPlayground`](https://github.com/trungnt2910/BootstrapPlayground/) is an example of
  this.
- Learn from the AI output and rewrite the solution yourself.
- Prefer traditional code generation & code refactoring tools to AI tools.

### DON'T
- Allow autonomous AI tools (AI "agents") to commit to `master` or open pull requests.
- Copy & paste verbatim output from AI tools.
- Use AI tools for deterministic refactoring tasks.

## Art

High-quality AI-generated art is allowed for marketing and social media materials.

For technical diagrams, the rules for [Documentation](#documentation) apply.
